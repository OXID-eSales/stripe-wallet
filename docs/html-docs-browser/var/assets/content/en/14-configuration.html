Configuration is data, not code.
Everything in metadata.php or the admin panel.

The Stripe module owns no environment files of its own — it reads OXID’s settings via PaymentConfigServiceInterface (a Payment-Base seam). Same surface for every PSP; same contract for the rest of the codebase to query.

Capture mode
  • sStripeCaptureMode = "automatic" — charge on PaymentIntent succeed
  • sStripeCaptureMode = "manual" — authorise only; admin captures from Stripe tab
  • Live changes apply on the next checkout — in-flight contracts keep their original mode
Availability filters
  • blStripeRemoveByBillingCountry — hide payment for non-matching billing countries
  • blStripeRemoveByBasketCurrency — hide payment when basket currency ≠ configured set
  • Allow-list editing lives on the same Extensions form; saved to oxconfig like every other OXID setting
Reading config at runtime
public function __construct(
    private PaymentConfigServiceInterface $config
) {}

public function isLive(): bool {
    return $this->config->getString('sStripeMode')
        === 'live';
}

public function isManualCapture(): bool {
    return $this->config->getString('sStripeCaptureMode')
        === 'manual';
}
Never Registry::getConfig()->getConfigParam() directly in Stripe code. The seam matters — in tests we inject a fake. A pre-commit grep guard fails the build if it finds the OXID call inside src/Stripe/.
