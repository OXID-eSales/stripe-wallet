Order Details → Stripe tab

One tab. Five cards. Zero DB snapshots.
The Stripe API is the source of truth.

The admin’s Stripe tab is rendered by OrderRefund: capture, refund, cancel-auth, reconcile. Display pulls live data from Stripe; the local DB is the audit log, not the cache.

What renders on the tab
  • Payment Details — contract id, order id, transaction id link, captured / refunded
  • Transaction History — live from Stripe with coloured badges
  • Capture form — partial supported
  • Refund form — validates remaining refundable
  • Cancel authorization — releases uncaptured auth
Storage strategy · B+
  • Display: Stripe API — always fresh, covers Dashboard actions
  • Audit log: oe_payments_transaction
  • Self-healing: reconcilePaymentState() on view fixes drifted OXPAID
Controller dispatch · one action per submit
public function dispatch(
    Order $o, string $action, array $req
): void {
    match ($action) {
        'capture' => $this->d->dispatch(
            new StripeCaptureRequestEvent(
                $o, $this->amount($req))),
        'refund'  => $this->d->dispatch(
            new StripeRefundRequestEvent(
                $o, $this->amount($req))),
        'cancel'  => $this->d->dispatch(
            new StripeCancelAuthorizationRequestEvent($o)),
    };
}
