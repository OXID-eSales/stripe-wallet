Order Details → Stripe tab

One tab. Five cards. Zero database snapshots.
The Stripe API is the source of truth.

The admin’s Stripe tab on the Order Details page is rendered by OrderRefund — the controller responsible for capture, refund, cancel-authorisation, and reconciliation. Display fetches live data from Stripe on each load; the local DB is the audit log, not the cache.

What renders on the tab
  • Payment Details — Contract ID, Order ID, Payment Type, Transaction ID linking to Stripe Dashboard, Captured amount, Refunded amount
  • Transaction History — from getStripeTransactionHistory() — coloured badges (auth / capture / refund / dispute)
  • Capture form — for manual-capture contracts in AUTHORIZED; supports partial
  • Refund form — for FULFILLED contracts with capture > 0; supports partial; validates remaining refundable
  • Cancel authorization — releases an uncaptured manual-capture auth
Storage strategy · B+
  • Display: Stripe API — always fresh, covers Dashboard actions outside our UI
  • Audit log: oe_payments_transaction — one row per action taken via OXID
  • Self-healing: reconcilePaymentState() runs on view — auto-fixes OXPAID when Stripe shows succeeded but OXPAID is blank
Controller dispatch · one action per submit
class OrderActionDispatcher
{
    public function dispatch(
        Order $order, string $action, array $req
    ): void {
        match ($action) {
            'capture' => $this->dispatcher->dispatch(
                new StripeCaptureRequestEvent(
                    $order, $this->amount($req)
                )
            ),
            'refund' => $this->dispatcher->dispatch(
                new StripeRefundRequestEvent(
                    $order, $this->amount($req)
                )
            ),
            'cancel' => $this->dispatcher->dispatch(
                new StripeCancelAuthorizationRequestEvent(
                    $order
                )
            ),
        };
    }
}
