Place Order creates a contract, not an order

The Smart-Contract lifecycle.
Eight states. Three terminal endings. Zero ambiguity.

Traditional checkout: click Place Order → order created → pay → update order. Smart-Contract: click Place Order → contract DRAFT → order NOT_FINISHED → Stripe session → customer pays → contract advances → order finalised. An order number exists before the Stripe redirect — refunds and audits never race the customer.

Conditions on the contract
  • payment_authorized — flips when Stripe confirms the PaymentIntent
  • stock_reserved — reservation handler hooks ContractCreatedEvent
  • fraud_check — optional, third-party hook point
Why this matters for Stripe
  • Order ID exists pre-redirect — passed to Stripe as metadata.order_id
  • BasketSnapshot immutably stored as JSON in OXBASKETDATA
  • OXORDERID stays NULL until COMMITTED — no orphan rows
  • Recovery flows attach to the contract, not the order — same vocabulary for every PSP
The Stripe module mutates nothing directly. It dispatches events — StripeCaptureRequestEvent, StripeRefundRequestEvent — and Payment-Base handlers advance the contract state. A pre-commit grep guard fails the build if any Stripe controller calls $contract->transitionTo() directly.
