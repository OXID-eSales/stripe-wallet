One click → Stripe Checkout → back to OXID.
Order number minted before the redirect.

The full flow
sequenceDiagram participant U as Customer participant S as OXID (cl=order) participant SC as StripeOrderController participant E as EventDispatcher participant CS as CheckoutSessionService participant SK as Stripe API U->>S: Click "Pay with Stripe" S->>SC: createCheckoutSession() SC->>E: dispatch(StripeCheckoutSessionRequestEvent) E->>CS: handle() (contract=DRAFT) CS->>CS: build BasketSnapshot CS->>CS: contract.transitionTo(NOT_FINISHED) CS->>CS: order = createOrder(NOT_FINISHED) CS->>SK: checkout.sessions.create(metadata={order_id}) SK-->>CS: session.url CS-->>U: 303 redirect → checkout.stripe.com U->>SK: pay (card / SCA / wallet) SK-->>U: 303 redirect → success_url U->>S: GET /cl=stripeorder?fnc=return&session_id=… S->>E: dispatch(StripeCheckoutReturnEvent) E->>CS: advance contract → READY_TO_COMMIT E->>S: finalize order → FULFILLED S-->>U: redirect → cl=thankyou
Guarantees of the flow
  • Order ID first. An OXID order row exists in NOT_FINISHED before Stripe sees the customer — refunds can’t race the redirect.
  • Idempotent return. Refresh the success page — the handler is a no-op when the contract is already FULFILLED.
  • Webhook safety net. If the customer closes the tab before the return, the webhook (slide 10) completes the order regardless.
  • Language preserved. success_url is rendered with the active OXID lang — customers don’t land on the wrong locale.
  • 3DS handled inline. When Stripe requires SCA, the redirect is the SCA challenge URL — no extra plumbing on our side.
