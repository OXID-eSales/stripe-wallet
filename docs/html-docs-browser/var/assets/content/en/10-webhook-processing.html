Features · 5 of 7 · Webhooks
Six guards before a byte of payload is parsed

The webhook endpoint is the most-attacked URL.
We harden it with guards, not prayers.

StripeWebhookController exposes one URL: ?cl=StripeWebhookController. Every request passes through an ordered chain of guards before any business logic runs. Guards are individually unit-tested, individually swappable via the service container, and short-circuit on first failure.

Guard chain (order matters)
  1. HttpsGuard — reject plain HTTP. Always.
  2. PayloadSizeGuard — cap raw body at 1 MB before parsing.
  3. RateLimitGuard — per-IP token bucket via APCu/redis (configurable).
  4. IpAllowlistGuard — optional Stripe egress range check.
  5. SignatureGuard — verify Stripe-Signature with the endpoint secret.
  6. IdempotencyGuard — event.id seen? log + 200, do not re-process.
Logged on every request
  • Raw payload + headers in oe_payments_webhooklogs
  • Which guard (if any) rejected, and why
  • The dispatched event class and handler latency
Handler dispatch · one switch per event type
match ($event->type) {
    'payment_intent.succeeded' =>
        $this->piSucceededHandler->handle($event),
    'payment_intent.payment_failed' =>
        $this->piFailedHandler->handle($event),
    'charge.refunded' =>
        $this->chargeRefundedHandler->handle($event),
    'charge.dispute.created' =>
        $this->disputeOpenedHandler->handle($event),
    default =>
        $this->logger->info(
            'Ignored Stripe event',
            ['type' => $event->type]
        ),
};
Why webhooks matter even when the redirect works
  • The customer’s browser may die between Stripe’s success page and our return URL — the webhook still closes the order.
  • Dashboard-initiated refunds bypass the admin tab — the webhook records them in oe_payments_transaction.
  • Disputes and chargebacks have no other entry point.
Always return 200 OK once parsed. Stripe retries on any non-2xx for 72 hours. A handler exception is caught at the controller boundary, logged, and the response is still 200 — but the event is flagged in oe_payments_webhooklogs for ops review.
