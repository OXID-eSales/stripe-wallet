Refund: validated, audited, idempotent.
Money never leaves twice.

Refunds are easy to get wrong. Stripe Wallet validates against the captured amount minus prior refunds in cents — never floats. Each refund records a transaction row, dispatches PaymentRefundedEvent, and triggers OpalReturns and any other PSP-agnostic subscriber.

RefundService · the path
public function refund(
    PaymentContract $contract,
    ?float $amount = null,
    ?string $reason = null
): RefundResult {
    $intent = $this->adapter->retrievePaymentIntent(
        $contract->getProviderIntentId()
    );

    $refundCents = $amount === null
        ? $this->refundHelper->remainingRefundable($intent)
        : (int) round($amount * 100);

    $this->refundHelper->assertRefundable(
        $intent, $refundCents
    );

    $refund = $this->adapter->refundCharge(
        $intent->latest_charge,
        amount: $refundCents,
        reason: $reason
    );

    $this->dispatcher->dispatch(
        new PaymentRefundedEvent($contract, $refund)
    );

    return RefundResult::fromRefund($refund);
}
RefundHelper’s job
  • remainingRefundable() = amountCaptured - sum(priorRefunds)
  • assertRefundable() throws if requested > remaining, or ≤ 0
  • Both methods are pure, integer-only, fully unit-tested
Idempotency · double-clicks can’t double-refund
  • Admin form posts with a CSRF token & a unique request_id.
  • oe_payments_idempotency row keyed by (contract_id, request_id) — replay hits the existing row, returns the prior result.
  • The Stripe SDK call also carries Idempotency-Key: {request_id} — Stripe itself rejects the duplicate.

class ReturnHandler implements HandlerInterface
{
    public function handle(
        PaymentRefundedEvent $e,
        EventContext $ctx
    ): void {
        $this->returnRepo->markRefunded(
            $e->getContract(),
            $e->getAmountCents()
        );
    }
}
