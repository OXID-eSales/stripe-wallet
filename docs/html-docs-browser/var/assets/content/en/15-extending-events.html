Add behaviour by adding handlers, not by editing existing ones

A new handler in three steps.
Write a class. Tag it. Test it.

The most common extension is a side-effect on a Stripe action — sending a Slack notification on refund, syncing a refund to a third-party ERP, freezing a loyalty point allocation on capture. None of these need to touch the Stripe module. They subscribe to a Payment-Base event and run alongside.

Step 1 · Implement HandlerInterface
namespace Acme\StripeNotifier;

use OxidEsales\Payments\Component\
    EventSystem\Event\PaymentRefundedEvent;
use OxidEsales\Payments\Component\
    EventSystem\HandlerInterface;
use OxidEsales\Payments\Component\
    EventSystem\EventContext;

final class SlackRefundNotifier
    implements HandlerInterface
{
    public function __construct(
        private SlackClient $slack
    ) {}

    public function handle(
        object $event,
        EventContext $ctx
    ): void {
        if (!$event instanceof PaymentRefundedEvent) {
            return;
        }
        $this->slack->post(sprintf(
            'Refund €%.2f on order %s',
            $event->getAmountCents() / 100,
            $event->getContract()->getOrderNumber()
        ));
    }
}
Step 2 · Tag in services.yaml
Acme\StripeNotifier\SlackRefundNotifier:
    arguments: ['@Acme\Slack\SlackClient']
    tags:
        - { name: payment.event_handler,
            event: PaymentRefundedEvent,
            priority: 10 }
Step 3 · Unit test in isolation
public function testPostsToSlack(): void
{
    $slack = $this->createMock(SlackClient::class);
    $slack->expects($this->once())
        ->method('post')
        ->with($this->stringContains('€42.00'));

    $h = new SlackRefundNotifier($slack);
    $h->handle(
        new PaymentRefundedEvent(
            $contract, $refund = $this->refund(4200)
        ),
        new EventContext()
    );
}
What you should not do
  • Don’t edit oe_payments_stripe_wallet. Adding code there couples a feature to a PSP — the boundary rule prohibits it.
  • Don’t subscribe to a Stripe-specific event if a PSP-agnostic equivalent exists. Use PaymentRefundedEvent over StripeRefundRequestEvent whenever you can — the handler then works for PayPal and future PSPs too.
  • Don’t call the Stripe SDK from your handler. If you must, depend on PaymentAdapterInterface — never new \Stripe\StripeClient().
