React to a Stripe event we don’t handle yet

A custom webhook handler.
Same pattern: implement, tag, test.

Default install handles payment_intent.succeeded / .payment_failed and charge.refunded. For anything else — disputes, fraud warnings, payouts — add a handler.

WebhookHandlerInterface
interface WebhookHandlerInterface
{
    public static function supportedTypes(): array;

    public function handle(
        \Stripe\Event $event,
        EventContext $ctx
    ): void;
}
Example · dispute opened
final class DisputeOpenedHandler
    implements WebhookHandlerInterface
{
    public static function supportedTypes(): array
    {
        return ['charge.dispute.created'];
    }

    public function handle($event, $ctx): void
    {
        $c = $this->contracts->findByChargeId(
            $event->data->object->charge
        );
        $c && $this->dispatcher->dispatch(
            new DisputeOpenedEvent($c, $event)
        );
    }
}
Tag it · services.yaml
Acme\Stripe\DisputeOpenedHandler:
    arguments:
        - '@…ContractRepositoryInterface'
        - '@…EventDispatcherInterface'
    tags:
        - { name: stripe.webhook_handler }
What you get for free
  • Signature, size, rate-limit & idempotency guards have already passed.
  • The \Stripe\Event is hydrated — not raw JSON.
  • Entry + exit timings logged in oe_payments_webhooklogs.
  • Handler throws → 200 still returned, exception logged, event flagged.
One handler per Stripe type. Need multiple effects? Dispatch a Payment-Base event and fan out.
