React to a Stripe event we don’t handle yet

A custom webhook handler.
Same pattern: implement, tag, test.

The default install handles payment_intent.succeeded, payment_intent.payment_failed, and charge.refunded. To react to anything else — charge.dispute.created, radar.early_fraud_warning.created, payout.paid — add a webhook handler.

WebhookHandlerInterface
namespace OxidEsales\Payments\Stripe\WebhookHandler;

interface WebhookHandlerInterface
{
    /** Stripe event types this handler responds to. */
    public static function supportedTypes(): array;

    public function handle(
        \Stripe\Event $event,
        EventContext $ctx
    ): void;
}
Example: dispute opened
final class DisputeOpenedHandler
    implements WebhookHandlerInterface
{
    public function __construct(
        private ContractRepositoryInterface $contracts,
        private EventDispatcherInterface $dispatcher,
    ) {}

    public static function supportedTypes(): array
    {
        return ['charge.dispute.created'];
    }

    public function handle(
        \Stripe\Event $event,
        EventContext $ctx
    ): void {
        $charge = $event->data->object->charge;
        $contract = $this->contracts
            ->findByChargeId($charge);
        if ($contract === null) return;

        $this->dispatcher->dispatch(
            new DisputeOpenedEvent($contract, $event)
        );
    }
}

What you get for free
  • The signature, payload size, rate-limit, and idempotency checks have already passed before your handle() runs.
  • The decoded \Stripe\Event is hydrated — not a raw JSON blob.
  • The webhook controller logs entry + exit timings — visible in oe_payments_webhooklogs.
  • If your handler throws, the controller still returns 200; the exception is logged and the event flagged for ops.
Don’t register more than one handler per Stripe type in production — ordering is undefined. If you need multiple effects, dispatch a Payment-Base event from your single webhook handler and let listeners fan out.
