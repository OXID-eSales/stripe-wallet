The Stripe reference implementation

Stripe Wallet =
Stripe Checkout, the Payment-Base way.

oe_payments_stripe_wallet is a thin adapter between Stripe's APIs and the Payment-Base spine. It owns no domain model, owns no database tables, and never imports another PSP. Everything PSP-agnostic stays in Payment Base; everything Stripe-specific lives here.

1

Stripe Checkout flow

Hosted Checkout Sessions with automatic 3D Secure. Customer redirects to Stripe, returns to an OXID order already created in NOT_FINISHED state.

2

Capture & Refund

Automatic or manual capture. Full and partial refunds. Authorization release on partial capture. All driven by admin-tab actions.

3

Webhook processor

HTTPS / IP / rate-limit / payload-size guards, signature verification, idempotency — 6 surfaces hardened by default.

4

Admin Stripe tab

Order Details → Stripe: live transaction history from Stripe API, capture / refund / cancel forms, OXPAID reconciliation.

~33 service files. Capture/, Refund/, Checkout/, Reconciliation/, factories & result objects. Every one has a single responsibility.
8 Stripe-specific events · 9 handlers. StripeCheckoutSessionRequestEvent, StripeCaptureRequestEvent, StripeRefundRequestEvent, … — PSR-14 throughout.
822+ unit tests · 18 integration tests. Test pyramid, AAA structure, testable subclass pattern for OXID admin controllers, final-class seam pattern.
