Developer docs · 1 of 5 · Setup
From clean checkout to a live test payment in under five minutes

Installation in three command groups.
Composer, the OXID console, then Stripe keys.

1 · Composer
$ composer require \
    oxid-esales/payment-component \
    oxid-esales/stripe-wallet
  • payment-component installs first — it owns the database tables
  • stripe-wallet ships as oxid-esales/stripe-wallet
  • Dev dependency: stripe/stripe-php ^19.3
2 · OXID console
$ bin/oe-console oe:module:install \
    extensions/stripe
$ bin/oe-console oe:module:activate \
    oe_payments_stripe_wallet
$ bin/oe-console oe:cache:clear
  • Activation creates the admin Stripe tab via metadata.php extensions
  • Cache clear re-builds DI container & Twig templates
  • No Doctrine migrations — payment-component owns all tables
3 · Stripe keys + webhook
Admin → Extensions
  → OE Payments · Stripe

  Mode:             test
  Test secret key:  sk_test_…
  Test publishable: pk_test_…
  Webhook secret:   whsec_…
  Capture mode:     automatic

Webhook URL: https://{shopUrl}/index.php?cl=StripeWebhookController
Add it in Stripe Dashboard → Developers → Webhooks.

Smoke test in 30 seconds. Place an order with card 4242 4242 4242 4242 — the Thank-You page should appear, the admin Stripe tab should list one capture transaction, and oe_payments_contract.OXSTATE should read FULFILLED. If any of the three is missing, the “Diagnose” button at the top of the Stripe tab will tell you which guard, handler, or webhook failed.
