Features · 3 of 7 · Capture
Full or partial · automatic or manual

Capture: full, partial, or never.
The contract reflects reality, not intent.

In automatic mode capture is immediate. In manual the contract waits in AUTHORIZED until an admin captures — partially, fully, or not at all.

CaptureService · the path
public function capture(
    PaymentContract $c,
    ?float $amount = null
): CaptureResult {
    $i = $this->adapter->retrievePaymentIntent(
        $c->getProviderIntentId()
    );

    $cents = $amount === null
        ? $i->amount
        : (int) round($amount * 100);

    $this->validator->assertCanCapture($i, $cents);

    $r = $this->adapter->capturePaymentIntent(
        $i->id, amount_to_capture: $cents
    );
    $this->dispatcher->dispatch(
        new PaymentCapturedEvent($c, $r)
    );
    return CaptureResult::fromIntent($r);
}
Validator gates
  • Intent is requires_capture or succeeded
  • Amount ≤ intent.amount_capturable and > 0
  • Contract owns this provider_intent_id
Partial capture — side effects
  • Authorization release. Stripe returns the uncaptured remainder to the customer.
  • Contract captured_amount updated by PaymentCapturedHandler.
  • OXPAID set on the linked order; reconciliation auto-heals drift.
  • Transaction row in oe_payments_transaction.
