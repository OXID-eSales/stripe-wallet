Full or partial · automatic or manual

Capture: full, partial, or never.
The contract reflects reality, not intent.

Stripe authorises the customer’s card during Checkout; capture moves the money. In automatic mode capture is immediate. In manual mode the contract waits in AUTHORIZED until an admin captures — partially, in full, or not at all.

CaptureService · the path
public function capture(
    PaymentContract $contract,
    ?float $amount = null
): CaptureResult {
    $intent = $this->adapter->retrievePaymentIntent(
        $contract->getProviderIntentId()
    );

    $captureAmount = $amount === null
        ? $intent->amount
        : (int) round($amount * 100);

    $this->validator->assertCanCapture(
        $intent, $captureAmount
    );

    $captured = $this->adapter->capturePaymentIntent(
        $intent->id,
        amount_to_capture: $captureAmount
    );

    $this->dispatcher->dispatch(
        new PaymentCapturedEvent($contract, $captured)
    );

    return CaptureResult::fromIntent($captured);
}
Validator gates
  • Intent must be requires_capture (manual) or succeeded (automatic)
  • Capture amount ≤ intent.amount_capturable
  • Capture amount > 0 (Stripe rejects zero captures)
  • Contract must own this provider_intent_id (no cross-contract drift)
Partial capture — the side effects
  • Authorization release. Stripe releases the unauthorised remainder back to the customer the moment a partial capture lands.
  • Contract field captured_amount is updated by PaymentCapturedHandler — the source of truth for the admin tab.
  • OXPAID column is set on the linked order. Reconciliation later auto-heals if it drifted from 0000-00-00.
  • Transaction row is inserted into oe_payments_transaction with type capture, intent id, amount, and admin user id.
