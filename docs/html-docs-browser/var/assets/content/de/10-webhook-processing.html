Features · 5 von 7 · Webhooks
Sechs Guards, bevor ein Byte Payload geparst wird

Der Webhook-Endpoint ist die meistangegriffene URL.
Wir härten ihn mit Guards, nicht mit Gebeten.

StripeWebhookController stellt eine URL bereit: ?cl=StripeWebhookController. Jede Anfrage durchläuft eine geordnete Kette von Guards, bevor Geschäftslogik startet. Guards sind einzeln unit-getestet, über den Service-Container austauschbar und brechen beim ersten Fehlschlag ab.

Guard-Kette (Reihenfolge zählt)
  1. HttpsGuard — Klartext-HTTP abweisen. Immer.
  2. PayloadSizeGuard — Rohbody auf 1 MB begrenzen, vor dem Parsen.
  3. RateLimitGuard — Token-Bucket pro IP via APCu/Redis (konfigurierbar).
  4. IpAllowlistGuard — optionale Prüfung der Stripe-Egress-Ranges.
  5. SignatureGuard — Stripe-Signature mit Endpoint-Secret prüfen.
  6. IdempotencyGuard — event.id bekannt? Loggen + 200, nicht erneut verarbeiten.
Pro Anfrage geloggt
  • Rohpayload + Headers in oe_payments_webhooklogs
  • Welcher Guard (falls einer) abgelehnt hat, mit Grund
  • Der dispatchte Event-Klasse und die Handler-Latenz
Handler-Dispatch · ein Switch je Event-Typ
match ($event->type) {
    'payment_intent.succeeded' =>
        $this->piSucceededHandler->handle($event),
    'payment_intent.payment_failed' =>
        $this->piFailedHandler->handle($event),
    'charge.refunded' =>
        $this->chargeRefundedHandler->handle($event),
    'charge.dispute.created' =>
        $this->disputeOpenedHandler->handle($event),
    default =>
        $this->logger->info(
            'Stripe-Event ignoriert',
            ['type' => $event->type]
        ),
};
Warum Webhooks wichtig bleiben — auch bei funktionierendem Redirect
  • Der Browser des Kunden kann zwischen Stripes Erfolgsseite und unserer Return-URL sterben — der Webhook schließt die Bestellung trotzdem.
  • Dashboard-initiierte Refunds umgehen unseren Admin-Tab — der Webhook protokolliert sie in oe_payments_transaction.
  • Disputes und Chargebacks haben keinen anderen Eintrittspunkt.
Nach dem Parsen immer 200 OK zurückgeben. Stripe versucht bei Nicht-2xx 72 Stunden erneut. Eine Handler-Exception wird am Controller-Rand gefangen und geloggt — die Antwort bleibt 200, das Event ist aber in oe_payments_webhooklogs markiert.
