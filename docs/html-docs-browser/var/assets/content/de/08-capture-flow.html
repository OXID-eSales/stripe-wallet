Capture: voll, teilweise oder nie.
Der Vertrag bildet die Realität ab, nicht die Absicht.

Stripe autorisiert die Karte des Kunden während des Checkouts; Capture verschiebt das Geld. Im Automatik-Modus erfolgt das sofort. Im Manual-Modus bleibt der Vertrag in AUTHORIZED, bis ein Admin bucht — teilweise, in voller Höhe oder gar nicht.

CaptureService · der Pfad
public function capture(
    PaymentContract $contract,
    ?float $amount = null
): CaptureResult {
    $intent = $this->adapter->retrievePaymentIntent(
        $contract->getProviderIntentId()
    );

    $captureAmount = $amount === null
        ? $intent->amount
        : (int) round($amount * 100);

    $this->validator->assertCanCapture(
        $intent, $captureAmount
    );

    $captured = $this->adapter->capturePaymentIntent(
        $intent->id,
        amount_to_capture: $captureAmount
    );

    $this->dispatcher->dispatch(
        new PaymentCapturedEvent($contract, $captured)
    );

    return CaptureResult::fromIntent($captured);
}
Validator-Gates
  • Intent muss requires_capture (manuell) oder succeeded (automatisch) sein
  • Capture-Betrag ≤ intent.amount_capturable
  • Capture-Betrag > 0 (Stripe lehnt Null-Captures ab)
  • Vertrag muss Eigentümer dieser provider_intent_id sein (keine Cross-Vertrags-Drift)
Teil-Capture — die Nebenwirkungen
  • Autorisierungsfreigabe. Stripe gibt den nicht gebuchten Rest dem Kunden zurück, sobald eine Teil-Buchung erfolgt.
  • Vertragsfeld captured_amount wird vom PaymentCapturedHandler aktualisiert — Quelle der Wahrheit für den Admin-Tab.
  • OXPAID-Spalte wird auf der verknüpften Bestellung gesetzt. Die Reconciliation heilt später automatisch, falls sie auf 0000-00-00 stehen geblieben ist.
  • Transaktionszeile wird in oe_payments_transaction eingefügt: Typ capture, Intent-ID, Betrag, Admin-Benutzer-ID.
