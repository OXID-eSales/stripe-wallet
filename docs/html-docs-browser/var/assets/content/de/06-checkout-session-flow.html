End-to-End — vom Bestell-Klick bis zur Dankesseite

Ein Klick → Stripe Checkout → zurück zu OXID.
Bestellnummer steht vor dem Redirect.

Der komplette Ablauf
sequenceDiagram participant U as Kunde participant S as OXID (cl=order) participant SC as StripeOrderController participant E as EventDispatcher participant CS as CheckoutSessionService participant SK as Stripe API U->>S: Klick "Mit Stripe bezahlen" S->>SC: createCheckoutSession() SC->>E: dispatch(StripeCheckoutSessionRequestEvent) E->>CS: handle() (contract=DRAFT) CS->>CS: BasketSnapshot bauen CS->>CS: contract.transitionTo(NOT_FINISHED) CS->>CS: order = createOrder(NOT_FINISHED) CS->>SK: checkout.sessions.create(metadata={order_id}) SK-->>CS: session.url CS-->>U: 303 Redirect → checkout.stripe.com U->>SK: bezahlen (Karte / SCA / Wallet) SK-->>U: 303 Redirect → success_url U->>S: GET /cl=stripeorder?fnc=return&session_id=… S->>E: dispatch(StripeCheckoutReturnEvent) E->>CS: Vertrag → READY_TO_COMMIT E->>S: Bestellung finalisieren → FULFILLED S-->>U: Redirect → cl=thankyou
Garantien des Ablaufs
  • Bestellnummer zuerst. Eine OXID-Bestellung in NOT_FINISHED existiert, bevor Stripe den Kunden sieht — Rückerstattungen laufen nicht ins Leere.
  • Idempotenter Return. Erfolgsseite neu laden — der Handler ist ein No-Op, wenn der Vertrag bereits FULFILLED ist.
  • Webhook als Sicherheitsnetz. Schließt der Kunde den Tab vor dem Return, schließt der Webhook (Folie 10) die Bestellung trotzdem ab.
  • Sprache bleibt erhalten. Die success_url wird mit dem aktiven OXID-lang gerendert — keine falschen Locale-Sprünge.
  • 3DS inline geregelt. Verlangt Stripe SCA, ist der Redirect bereits die SCA-Challenge-URL — wir müssen nichts extra verkabeln.
