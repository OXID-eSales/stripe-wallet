Features · 1 von 7 · Stripe Checkout
End-to-End — vom Bestell-Klick bis zur Dankesseite

Ein Klick → Stripe → zurück zu OXID.
Bestellnummer steht vor dem Redirect.

Der komplette Ablauf
sequenceDiagram participant U as Kunde participant SC as StripeOrderController participant E as EventDispatcher participant CS as CheckoutSessionService participant SK as Stripe API U->>SC: Klick "Mit Stripe bezahlen" SC->>E: dispatch(StripeCheckoutSessionRequestEvent) E->>CS: handle() (contract=DRAFT) CS->>CS: BasketSnapshot bauen CS->>CS: contract.transitionTo(NOT_FINISHED) CS->>CS: order = createOrder(NOT_FINISHED) CS->>SK: checkout.sessions.create(metadata={order_id}) SK-->>CS: session.url CS-->>U: 303 Redirect → checkout.stripe.com U->>SK: bezahlen (Karte / SCA / Wallet) SK-->>U: 303 Redirect → success_url U->>SC: GET /cl=stripeorder?fnc=return SC->>E: dispatch(StripeCheckoutReturnEvent) E->>CS: Vertrag → READY_TO_COMMIT E->>SC: Bestellung finalisieren → FULFILLED SC-->>U: Redirect → cl=thankyou
Garantien
  • Bestellnummer zuerst. OXID-Zeile in NOT_FINISHED, bevor Stripe den Kunden sieht.
  • Idempotenter Return. No-Op, wenn der Vertrag schon FULFILLED ist.
  • Webhook-Netz schließt die Bestellung, falls der Browser stirbt.
  • Sprache erhalten via lang in success_url.
  • 3DS inline — Stripe behandelt die SCA-Challenge.
