Auf ein Stripe-Event reagieren, das wir noch nicht behandeln

Ein eigener Webhook-Handler.
Gleiches Muster: implementieren, taggen, testen.

Standardmäßig behandelt das Modul payment_intent.succeeded, payment_intent.payment_failed und charge.refunded. Um auf alles andere zu reagieren — charge.dispute.created, radar.early_fraud_warning.created, payout.paid — legt man einen Webhook-Handler an.

WebhookHandlerInterface
namespace OxidEsales\Payments\Stripe\WebhookHandler;

interface WebhookHandlerInterface
{
    /** Stripe-Event-Typen, auf die der Handler reagiert. */
    public static function supportedTypes(): array;

    public function handle(
        \Stripe\Event $event,
        EventContext $ctx
    ): void;
}
Beispiel: Dispute eröffnet
final class DisputeOpenedHandler
    implements WebhookHandlerInterface
{
    public function __construct(
        private ContractRepositoryInterface $contracts,
        private EventDispatcherInterface $dispatcher,
    ) {}

    public static function supportedTypes(): array
    {
        return ['charge.dispute.created'];
    }

    public function handle(
        \Stripe\Event $event,
        EventContext $ctx
    ): void {
        $charge = $event->data->object->charge;
        $contract = $this->contracts
            ->findByChargeId($charge);
        if ($contract === null) return;

        $this->dispatcher->dispatch(
            new DisputeOpenedEvent($contract, $event)
        );
    }
}

Was Sie kostenlos bekommen
  • Die Prüfungen für Signatur, Payload-Größe, Rate-Limit und Idempotenz sind bereits durchgelaufen, bevor Ihr handle() aufgerufen wird.
  • Das dekodierte \Stripe\Event ist hydratisiert — kein roher JSON-Blob.
  • Der Webhook-Controller loggt Start + Ende mit Timings — sichtbar in oe_payments_webhooklogs.
  • Wenn Ihr Handler wirft, antwortet der Controller trotzdem mit 200; die Exception wird geloggt und das Event für Ops markiert.
In Produktion nie mehr als einen Handler pro Stripe-Typ registrieren — die Reihenfolge ist undefiniert. Wer mehrere Effekte braucht, dispatcht aus dem einen Webhook-Handler ein Payment-Base-Event und lässt die Listener fan-out machen.
