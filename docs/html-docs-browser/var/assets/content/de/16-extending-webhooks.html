Auf ein Stripe-Event reagieren, das wir noch nicht behandeln

Ein eigener Webhook-Handler.
Gleiches Muster: implementieren, taggen, testen.

Standardmäßig behandelt das Modul payment_intent.succeeded / .payment_failed und charge.refunded. Für alles weitere — Disputes, Fraud-Warnings, Payouts — einen Handler anlegen.

WebhookHandlerInterface
interface WebhookHandlerInterface
{
    public static function supportedTypes(): array;

    public function handle(
        \Stripe\Event $event,
        EventContext $ctx
    ): void;
}
Beispiel · Dispute eröffnet
final class DisputeOpenedHandler
    implements WebhookHandlerInterface
{
    public static function supportedTypes(): array
    {
        return ['charge.dispute.created'];
    }

    public function handle($event, $ctx): void
    {
        $c = $this->contracts->findByChargeId(
            $event->data->object->charge
        );
        $c && $this->dispatcher->dispatch(
            new DisputeOpenedEvent($c, $event)
        );
    }
}
Taggen · services.yaml
Acme\Stripe\DisputeOpenedHandler:
    arguments:
        - '@…ContractRepositoryInterface'
        - '@…EventDispatcherInterface'
    tags:
        - { name: stripe.webhook_handler }
Kostenlos enthalten
  • Signatur-, Größen-, Rate-Limit- & Idempotenz-Guards sind durch.
  • Das \Stripe\Event ist hydratisiert — kein roher JSON-Blob.
  • Start + Ende mit Timings in oe_payments_webhooklogs.
  • Handler wirft → 200 bleibt, Exception geloggt, Event markiert.
Einen Handler pro Stripe-Typ. Mehrere Effekte? Aus dem Handler ein Payment-Base-Event dispatchen.
