Vom sauberen Checkout zur ersten Testzahlung in unter fünf Minuten

Installation in drei Befehls-Blöcken.
Composer, OXID-Konsole, Stripe-Keys.

1 · Composer
$ composer require \
    oxid-esales/payment-component \
    oxid-esales/stripe-wallet
  • payment-component wird zuerst installiert — es besitzt die Datenbanktabellen
  • stripe-wallet wird als oxid-esales/stripe-wallet ausgeliefert
  • Dev-Abhängigkeit: stripe/stripe-php ^19.3
2 · OXID-Konsole
$ bin/oe-console oe:module:install \
    extensions/stripe
$ bin/oe-console oe:module:activate \
    oe_payments_stripe_wallet
$ bin/oe-console oe:cache:clear
  • Die Aktivierung erstellt den Admin-Stripe-Tab via metadata.php-Extensions
  • Cache-Clear baut DI-Container & Twig-Templates neu
  • Keine Doctrine-Migrationen — payment-component besitzt alle Tabellen
3 · Stripe-Keys + Webhook
Admin → Extensions
  → OE Payments · Stripe

  Modus:                test
  Test Secret Key:      sk_test_…
  Test Publishable Key: pk_test_…
  Webhook-Secret:       whsec_…
  Capture-Modus:        automatic

Webhook-URL: https://{shopUrl}/index.php?cl=StripeWebhookController
Im Stripe-Dashboard unter Developers → Webhooks eintragen.

Smoke-Test in 30 Sekunden. Mit Karte 4242 4242 4242 4242 eine Bestellung aufgeben — die Dankesseite muss erscheinen, der Admin-Stripe-Tab muss eine capture-Transaktion zeigen, und oe_payments_contract.OXSTATE muss auf FULFILLED stehen. Fehlt eines davon, sagt der „Diagnose“-Button oben im Tab, welcher Guard, Handler oder Webhook ausgefallen ist.
