Refund: validiert, geloggt, idempotent.
Geld geht nie zweimal raus.

Rückerstattungen sind leicht falsch zu machen. Stripe Wallet validiert gegen den gebuchten Betrag abzüglich vorheriger Erstattungen in Cent — niemals in Floats. Jede Erstattung schreibt eine Transaktionszeile, dispatcht PaymentRefundedEvent und triggert OpalReturns sowie jeden weiteren PSP-unabhängigen Subscriber.

RefundService · der Pfad
public function refund(
    PaymentContract $contract,
    ?float $amount = null,
    ?string $reason = null
): RefundResult {
    $intent = $this->adapter->retrievePaymentIntent(
        $contract->getProviderIntentId()
    );

    $refundCents = $amount === null
        ? $this->refundHelper->remainingRefundable($intent)
        : (int) round($amount * 100);

    $this->refundHelper->assertRefundable(
        $intent, $refundCents
    );

    $refund = $this->adapter->refundCharge(
        $intent->latest_charge,
        amount: $refundCents,
        reason: $reason
    );

    $this->dispatcher->dispatch(
        new PaymentRefundedEvent($contract, $refund)
    );

    return RefundResult::fromRefund($refund);
}
Aufgabe des RefundHelper
  • remainingRefundable() = amountCaptured - sum(priorRefunds)
  • assertRefundable() wirft, wenn angefordert > verbleibend oder ≤ 0
  • Beide Methoden rein, nur Integer, vollständig unit-getestet
Idempotenz · Doppelklick erstattet nicht doppelt
  • Das Admin-Formular postet mit CSRF-Token und eindeutiger request_id.
  • Eine Zeile in oe_payments_idempotency mit Schlüssel (contract_id, request_id) — Replay trifft die bestehende Zeile und gibt das vorherige Ergebnis zurück.
  • Der Stripe-SDK-Aufruf trägt zusätzlich Idempotency-Key: {request_id} — Stripe selbst weist Duplikate zurück.
