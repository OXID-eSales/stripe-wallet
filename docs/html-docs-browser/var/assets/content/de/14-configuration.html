Konfiguration ist Daten, nicht Code.
Alles in metadata.php oder im Admin-Panel.

Das Stripe-Modul besitzt keine eigenen Environment-Dateien — es liest OXIDs Settings über PaymentConfigServiceInterface (eine Payment-Base-Naht). Gleiche Oberfläche für jeden PSP; gleicher Vertrag für den Rest des Codebases.

Capture-Modus
  • sStripeCaptureMode = "automatic" — bei PaymentIntent-Erfolg sofort buchen
  • sStripeCaptureMode = "manual" — nur autorisieren; Admin bucht aus dem Stripe-Tab
  • Änderungen wirken auf den nächsten Checkout — laufende Verträge behalten ihren ursprünglichen Modus
Verfügbarkeits-Filter
  • blStripeRemoveByBillingCountry — Zahlart bei nicht zugelassenem Rechnungsland ausblenden
  • blStripeRemoveByBasketCurrency — ausblenden, wenn Warenkorb-Währung ≠ konfigurierte Menge
  • Allow-List-Pflege im selben Extensions-Formular; in oxconfig wie jede OXID-Einstellung gespeichert
Konfiguration zur Laufzeit lesen
public function __construct(
    private PaymentConfigServiceInterface $config
) {}

public function isLive(): bool {
    return $this->config->getString('sStripeMode')
        === 'live';
}

public function isManualCapture(): bool {
    return $this->config->getString('sStripeCaptureMode')
        === 'manual';
}
Nie Registry::getConfig()->getConfigParam() direkt in Stripe-Code. Die Naht zählt — im Test injizieren wir einen Fake. Ein Pre-Commit-Grep-Guard lässt den Build scheitern, wenn der OXID-Aufruf in src/Stripe/ auftaucht.
