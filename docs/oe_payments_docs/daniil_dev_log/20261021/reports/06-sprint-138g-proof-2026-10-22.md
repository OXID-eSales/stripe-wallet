## 138g

- `Adapter/PayPalWebhookSignatureVerifierInterface` (`isAuthentic(webhookId, headers, rawBody)`), `PayPalWebhookSignatureVerifier`, `PayPalRestTransportInterface` + `CurlPayPalRestTransport` (raw REST boundary; `paypal-server-sdk` has no `verify-webhook-signature`). Name deviates from the spec because `WebhookHandler\WebhookSignatureVerifierInterface` already exists.
- Request to `/v1/notifications/verify-webhook-signature` on the mode's API base; the delivery body is spliced in byte for byte (re-encoding would turn `"10.00"` into `10`); only the exact string `SUCCESS` passes; missing/empty transmission headers, non-JSON body, transport error, missing webhook id or verifier → reject (fail closed); exception messages carry only the HTTP status.
- `PayPalAdapter::verifyAndParse()` verifies before parsing; `PayPalAdapterFactory` takes the transport; `services.yaml` wired. G2: the idempotency key `paypal_webhook:<eventId>` is claimed after verification (`WebhookControllerVerificationTest`: 400 without claiming or processing, order verify → claim → fulfill → processed). G4: CHANGELOG (Security, upgrade note), `docs/for_merchant/01-setup.md` and `03-troubleshooting.md` (webhook id mandatory, outbound HTTPS to PayPal).
- Tests red → green: `testVerify_MissingTransmissionHeaders_Rejects`, `testVerify_SignatureFailure_Rejects`, `testVerify_Valid_Parses`, plus per-header, per-status, transport-failure, header-case and raw-body tests.
