## Stories

- **B1** `src/Checkout/Headless/HeadlessTokenHash.php` (readonly, `fromToken()`, `fromStored()`, `matches()` with sha256 + `hash_equals`; no salt, the token is 128-bit random). `start()` stores the hash, `authorisedContract()` compares hashes; a stored hash presented as the token never matches. Tests: `HeadlessTokenHashTest`, `testAuthorisedContract_PlaintextTokenInMetadata_IsRefused`, `testStart_AnyRequest_StoresOnlyTheHashAndAnswersThePlaintextToken`.
- **B2** Migration selects rows whose `OXMETADATA` contains `headless_token`, hashes in PHP, updates by OXID with parameters (no `JSON_SET`: the column is latin1 longtext and MySQL would re-encode the document). Idempotent (64-hex values skipped), `down()` irreversible. Integration: `tests/Integration/Migrations/HeadlessTokenHashMigrationTest.php` (3 tests). **Deploy note:** run `bin/run-migrations.sh` with the update or open attempts fail with `invalid_token`.
- **B3** `ClientConfigGuard::assertPublic(array $values, ?array $allowedNames = null)`; `AllowListedClientConfigProviderInterface extends ClientConfigProviderInterface` with `publicValueNames()`. Deviation from the spec: a **second optional interface** instead of a method on the existing one (PHP interfaces have no default; adding the method would fatal the three modules). A provider without it stays on deny shapes only; a provider with it is locked to its names (`[]` refuses everything). Registry-level proof in `ClientConfigPublisherTest::testSealedFor_ProviderDeclaresNames_RefusesAnUndeclaredNameWithAHarmlessValue`. The modules implement the interface in 140b/139 work (stripe `publishableKey`, paypal `clientId`, mollie `profileId`, `testMode`).
- **B4** CHANGELOG [Unreleased] "Security", docs note on the hash. CI files untouched.
