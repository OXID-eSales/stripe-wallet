# Subsprint 140a proof — payment-base: anonymous rights and the guest user

**Date:** 2026-10-22 · **Repo:** payment-base, branch `feature/graphql-comply` · **Spec:** [`../done/sprint-140a-backend-rights-and-guest-user.md`](../done/sprint-140a-backend-rights-and-guest-user.md)

## Decision gate (A1 spike, SDK shop, rights granted in the working tree, reverted, spike rows deleted)

| Probe with an anonymous token                                   | Result                                                                                      |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `query { token }`                                               | works; JWT `useranonymous: true`, `username: ""`, random `userid` without an `oxuser` row    |
| `basketCreate`                                                  | works; `owner: null`; `oxuserbaskets.OXUSERID` is empty                                     |
| `basketAddItem`, `basket(basketId)`                             | work                                                                                        |
| another anonymous token on that basket                          | allowed (ownerless; the 128-bit basket id is the only secret, as in the storefront today)   |
| anonymous token on a logged-in user's basket                    | refused ("belongs to somebody else")                                                        |
| `basketSetPayment/DeliveryMethod/DeliveryAddress`, `basketPayments` | `@Logged`, absent from the anonymous schema                                            |
| `placeOrder`                                                    | insufficient rights (no `PLACE_ORDER` granted, by design)                                   |
| `stripe/mollie/paypalCheckoutStart`                             | visible with `PAYMENT_CHECKOUT`                                                             |

**Decision: variant (a)** — anonymous basket, guest account created or matched at `checkoutStart`, basket re-owned to it. Consequence for 140b: the guest start must carry the `paymentId` (anonymous tokens cannot `basketSetPayment`).

## Input shape (binding for 140b and 140c)

`HeadlessStartRequest(..., array $providerOptions = [], ?GuestDetails $guest = null)`;
`GuestDetails(string $email, GuestAddress $invoiceAddress, ?GuestAddress $deliveryAddress = null)`;
`GuestAddress(firstName, lastName, street, streetNumber, zipCode, city, countryId, salutation = '', company = '', additionalInfo = '', stateId = '', phone = '')`.
Validation in the constructors throws `HeadlessCheckoutException(guest_details_required)` naming the field, never the value. New codes: `guest_details_required`, `account_exists`.

## Behaviour

- Anonymous token without details → `guest_details_required`; registered e-mail (account with password) → `account_exists`, account untouched, basket stays unowned; passwordless account → reused, invoice fields refreshed, delivery address replaced; new e-mail → guest account (`oxpassword=''`, `oxrights='user'`, no `oxregister`).
- Basket claim: ownerless → guest's; same guest again idempotent; other owner → `basket_forbidden`; missing → `basket_not_found`. `UserBasketProvider` unchanged.
- Behaviour change: a token whose user is missing now yields `guest_details_required` instead of `user_not_found`.

## Proof

Unit 1644 → 1681, integration 154 → 159 (`GuestCheckoutStartTest`, 5 tests on the real shop with a fake PSP handler: READY_TO_COMMIT with the guest as `userId`, reuse, `account_exists`, `basket_forbidden`, delivery address in `oxaddress` + `OEGQL_DELADDRESSID`). Gate `--full` green (see report 03). CI 7.4/7.5/7.6 green on `dd214e9`.

## Open (carried into 140b/140c)

- The contract-first flow does not apply a basket's delivery address to the order (`UserBasketProvider` ignores `OEGQL_DELADDRESSID`) for guests and logged-in users alike; the order ships to the invoice address. Needed for the 140 acceptance "order with the guest's addresses".
- Guest accounts have no `oxregister`, so `customer { orders }` is empty for them.
- Guest accounts and address rows accumulate; no cleanup; no rate limiting of anonymous starts.
- `composer.json` not bumped, no tag: release 1.5.0 is the user's step (CHANGELOG entries under [Unreleased]).
- During spike cleanup orphan `oxuserbasketitems` rows of the local SDK database were deleted once.
