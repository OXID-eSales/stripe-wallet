## 138e — the browser keeps only what the next request needs (decision: variant (a))

- **E1 (core `7a86410`):** `AuthService.logout(): Promise<void>` sends `tokenDelete(tokenId)` (claim `tokenid`) with the old bearer before clearing; a failed revoke still clears and never rejects; nothing is sent without a token or past `exp`.
- **E2 (core `7a86410`):** `login` → access + refresh token; `SessionRefresher` refreshes at remaining − min(60 s, 25 %) with the `fingerprintHash` claim, without a bearer; a refused refresh drops the session through the rejected-token path; transport failures retry every 30 s while the token lives; concurrent refreshes share one request; a refresh answer after logout is discarded; feature detection falls back to `token` (never on `invalid_login`); `refreshFlow: false` skips `login`. Refresh token in `localStorage` `oxfe.refresh` next to the JWT: no more exposed than the JWT it renews and useless without the HttpOnly fingerprint cookie. Verified live against the SDK shop with curl: `refresh` without the cookie answers "Fingerprint missing" and the client drops the session.
- **E3 (user `55e61e1`):** the checkout plugin clears `oxfe_checkout_attempt` on `CoreEvents.AuthLogout`; `ReturnView` clears on failed, committed and after the pending wait; cancel already cleared. Deviation: a return failing with `network_error`/`http_error` keeps the attempt (an unreachable shop is no verdict). Unit `checkoutAttempt.spec.ts`; e2e `checkout-attempt.spec.ts` (9) asserts `sessionStorage` after committed/failed/pending/cancel/logout with mocked provider answers.
- **E4:** `docs/architecture.md` "Sessions: what the browser keeps, where, and for how long"; core `CHANGELOG.md`/README.
- **Open:** `sJsonWebTokenLifetime` is shop configuration and was not shortened; the refresh flow has fake-timer unit tests and a curl contract check, no e2e on a short-lifetime shop. The rejected-token handler does not try a refresh before dropping (clock skew / early revocation); no `visibilitychange` listener (hosts keep calling `ensureSession()` on navigation).
