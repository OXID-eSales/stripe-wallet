## 2. Playwright — `opc-175-coupon-survives-payment-switch.spec.ts`

Repo `one-page-checkout/tests/e2e/e2e-tests-playwright` (own git), branch `OPC-175-coupon-payment-switch-e2e` (local, not committed).
The spec drives the storefront endpoints (`setPaymentMethod`, `processCheckout`, `getSummary`) and reads the DB after each step. It never pays.
Run: `SHOP_URL=https://daniil.oxiddev.de npx playwright test tests/one-page-checkout/opc-175-coupon-survives-payment-switch.spec.ts --project=chromium`

| Step (each direction: Stripe → Mollie, Mollie → Stripe, PayPal → Stripe) | Result |
|---|---|
| Coupon `E2E_5FLAT` applied, discount 5.00 | ✓ |
| First Place Order: one early order, it holds the voucher row | ✓ |
| Coupon still in the basket after the first Place Order | **✗ discount 0** |
| Change of the payment method: basket total | **1325 instead of 1320** |
| Second Place Order succeeds | ✓ |
| Earlier attempt `CANCELLED` + `OXSTORNO = 1` | ✓ (S1) |
| Exactly one `NOT_FINISHED` order in the session | ✓ (S1) |
| The voucher belongs to the open order | **✗ no order holds it** |

**Why the coupon disappears at the first Place Order.** `finalizeOrder()` marks the voucher row as used by the new early order. The next recalculation (`getSummary` here; in the storefront the modal refresh) calls `Voucher::isAvailable()`. It refuses the row, because `OXORDERID` is set — to the session's **own** open order — and core drops the voucher. The OPC-185 restore in `setPaymentMethod()` sees nothing to restore any more (G5). The retire then releases the row, but the basket no longer has the voucher, so the next order is created without it.

**Effect of S1.** Before S1 the OPC Stripe path never retired an attempt (G1/G2). In all three directions the earlier attempt is now cancelled and stornoed, and only one order is open. Mollie → Stripe and PayPal → Stripe could not pass this check before S1 (the Stripe handler created its order directly).

**Test hygiene in the spec.** Before each test it ends the e2e user's open attempts of the last 24 h (contract cancelled, order stornoed, vouchers released) and frees the `E2E_5FLAT` rows of unpaid orders. Without this, Stripe hands back the previous run's checkout (in-flight reuse: same user, same amount) and no new attempt is made. One run showed discount 0 directly after `applyVoucher`; it did not repeat in 5 later runs. Watch it.

## 4. Stock

Measured with `OXSTOCK = 100` on the test product (restored to 0 afterwards): after two attempts (one retired, one open) the stock is **98**. Each early order takes the stock, and the retire (`deleteNotFinishedOrder()` → SQL storno) does **not** restock. Each retired attempt loses one unit for good. New gap **G9**. The adoption (section 4) avoids it: one order, one stock reservation. The fallback retire still needs a restock (add to S4 or a follow-up).
